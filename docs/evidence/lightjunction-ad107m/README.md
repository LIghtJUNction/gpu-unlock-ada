- 驱动 RM 只读接口的 `fmla32`、`imla2`、`imla4` 从安装前的 `1` 变为 `0`。
  对此接口，`1` 表示半速，`0` 表示全速；其他已查询字段均保持 `0`。

## 实际执行的计算检查

使用本机 CUDA `13.4.92`，以 `-O3 -arch=sm_89 -std=c++17` 编译仓库中的两个
现有程序，链接本机 cuBLAS。程序和输入源码的 SHA-256 保存在 [metadata.json](metadata.json)。

1. `diagnostics/bench/validate_gemm.cu`：FP16/BF16 输入、FP32 累加，分别检查
   `256×256×256`、`64×96×128`、`127×65×95` 三个形状和三个种子。6 组均通过，
   与 CPU 参考的最大绝对误差均为 `0`，共核对 `159870` 个输出值。
2. `docs/evidence/rtx4090-pr1-stock/gemm_bench.cu`：FP16/BF16 分别计算
   `1024³`、`4096³`、`8192³`。每组 10 次预热，5 轮计时、每轮 20 次 GEMM，
   共 660 次 GEMM。各组最后一次输出的每个元素均核对通过，合计 `169869312`
   个值，没有不匹配。此程序使用可廉价精确核对的简单输入，不能代替上面的
   不同输入检查，也不能证明任意应用的数值正确性。

[numerical.txt](numerical.txt) 与 [gemm.jsonl](gemm.jsonl) 保留原始数值结果。
整个采集约 23.5 秒，其中 GPU 负载并不连续。33 个遥测采样的温度范围为
64–82°C，功耗范围为 27.57–81.79 W，SM 时钟为 2565–2595 MHz；这些是短时
采样范围，不是硬件极限值。负载后实际速率仍为全速，日志中没有 `NVRM: Xid`，
也没有新增驱动断言。

## 警告与证据边界

- 本次启动已有两条 `NV_ERR_INVALID_DATA` 断言：从 SBIOS 获取目标温度和平台
  功耗模式失败。原文保存在 `boot-check.json`。NVIDIA/CUDA 继续运行，计算检查
  通过，`nvidia-powerd` 运行中；尚未确定这两条断言的原因，不能称为完全无警告。
- 桌面持续使用独显，测试前 GPU 利用率约 53%，没有停止用户应用。因此
  `gemm.jsonl` 的时间和吞吐仅作为本次诊断原始输出，不作为隔离条件下的跑分。
  没有采集同卡原厂状态的吞吐，也没有定位性能瓶颈；本记录不声称提升百分比。
- 只观察到一次本机实验启动，没有独立确认 EC 断电状态。普通重启、挂起恢复、
  驱动重载、长期空闲和长期计算均未验收。实验项关闭独显运行时自动断电，
  可能增加待机耗电。
- 没有游戏帧率、推理、训练或其他完整应用的前后对照。全速字段和数值检查
  不等于实际应用达到 2 倍性能。

日志已去除 GPU UUID、PCI 位置、主机名、根文件系统标识和私有路径；设备型号、
子设备及芯片值保留用于核对硬件范围。没有提交固件、模块或测试二进制。
选择普通 `Omarchy/linux` 可回到不执行解锁的启动流程；恢复稳定的原厂状态应
从完全关机后启动普通项，不依赖一次热重启清除 GPU 状态。
